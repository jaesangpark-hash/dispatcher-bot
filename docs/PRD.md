# PRD — 능동 선제 대응 에이전트

작성: 박재상 · 2026-09-03 · v1

| 항목 | 내용 |
|---|---|
| 한 줄 요약 | 작품·회차 문의 수신 시 원본·에디터 링크·과거 로그를 내가 명령하기 전에 자동 제공 |
| 문제 (Pain Point) | ① 규칙화 가능한 패턴(원본 파일 줘, 에디터 링크 줘, 납품일 확인해 등)을 매번 내가 직접 명령해야 정보를 받을 수 있음 ② 내부 공유 메시지 초안 요청 시 봇 출력이 업무 톤앤매너와 맞지 않음 |
| 목표 | 규칙화할 수 있는 패턴의 명령을 내가 직접 입력하는 일이 없어진다 |
| 사용자 | 박재상 (메인) |
| 핵심 기능 | ① 특정 작품·회차 문의 스레드 수신 → 원본 관련이면 원본 파일 링크 자동 제공 ② 상황 분석 후 Totus 에디터 링크 자동 제공 (상황에 맞는 오퍼레이션 에디터) ③ 이전 유사 문의 로그 조회 → 관련 조언 제공 |
| 입력 → 출력 | 작품·회차 관련 슬랙 문의 스레드 수신 → 원본 파일 링크·에디터 링크·과거 로그 요약을 나에게 DM으로 자동 제공 |
| 데이터 · 도구 | 슬랙 (문의 스레드 수신 · DM 발송) / 구글 시트 (원본·납품 현황) / Totus (에디터 링크) / 과거 문의 로그 (저장 방식 미정) |
| 안 할 것 (이번 범위) | 없음 — 가능한 부분은 모두 시도 |
| 완성 기준 | 규칙화 가능한 패턴 명령(원본 파일 줘, 에디터 링크 줘, 납품일 확인해 등)을 내가 직접 입력하는 일이 없어진다 |

## 서브 프로젝트
- **툰식이 원본 자동 이관**: 원본 재수급 완료 시 PIVO 업로드 → Totus 전송 → 성공·실패 알림 (메인 완성 후 또는 병행)

## 아웃풋 톤앤매너
- 내부 공유 메시지 초안 요청 시 업무 스타일에 맞게 출력
- 기준 예시: 추후 업데이트

## 필요한 권한·API (운영진 확인 요청)
- Totus 에디터 링크 조회 방식 확인 필요 (API 있는지, 있다면 엔드포인트·인증 방식)
- 구글 시트 읽기 접근 방식 확인 필요 (서비스 계정 or OAuth)
- 과거 문의 로그 저장 위치·형식 결정 필요 (슬랙 히스토리 조회 vs 봇 내부 저장)
